Prepriprava:
1) vytvorime image 1.3.0: docker build -t dawiso-demo:1.3.0 --build-arg APP_VERSION=1.3.0 .
2) naloadime image do clusteru: kind load docker-image dawiso-demo:1.3.0 --name dawiso-lab

Musi byt: 
kubectl config current-context        # kind-dawiso-lab
kubectl get pods -n argo              # argo-server a workflow-controller Running
argo version --short                  # argo: v4.1.4
kubectl get pods -n demo-dev          # demo běží
docker exec dawiso-lab-worker crictl images | Select-String dawiso-demo   # musí tam být 1.3.0

------

Instalace Argo WF a CLI:
1) kubectl create namespace argo
2) udelame apply WFs z githubu: kubectl apply --server-side -n argo -f https://github.com/argoproj/argo-workflows/releases/download/v4.1.4/quick-start-minimal.yaml 
3) kubectl get pods -n argo -w   --> check
4) kubectl -n argo port-forward service/argo-server 2746:2746 -> port forward pro argo-server
5) https://localhost:2746/workflows/argo?limit=50 --> je tam wf hello-world se staved succeeded

Smoke test
1) Vytvoříme template pro workflow ktera bude delat curl na service dema -> potrebuje env a version kde a najkou verzi se bude curl delat -> kind WorkflowTemplate, namespace argo, nastavujeme spec -> templates, arguments, ...
2) argo lint --offline workflows\dawiso-demo-smoke-test-template.yaml --> prelozi wf file najde chyby
3) kubectl apply -f workflows\dawiso-demo-smoke-test-template.yaml -> aplikujeme
4) argo template list -n argo -> vypise templates v argo -> delame pro check
5) pozitivni test: argo submit -n argo --from workflowtemplate/dawiso-demo-smoke-test-template -p env=dev -p version=1.2.0 --watch
    -> projde ok, dev bezi na version=1.2.0 
6) negativni test: argo submit -n argo --from workflowtemplate/dawiso-demo-smoke-test-template -p env=dev -p version=7.7.7 --watch
    -> mel by failnout celkove 6x podle nastavene template s danym backoff
7) argo get '@latest' -n argo --> vypise vysledek latest wf, pozor '' -> jsou potreba skrz powershell
    -> argo get dawiso-demo-smoke-test-template-p2r7t -n argo --> vysledek pro wf s konretnim jmenem -> vyzaduje namespace vzdy !!!
    -> argo list -n argo ---> vypise wfs co probehly/beziS
    -> argo logs -n argo '@latest'  --> vypise logy z workflowtemplate

Token pro zápisu do Gitu:
1) vygenerovat si token na github account pro gitops repo na content read and write
2) ulozit do clusteru:
$t = Read-Host "GitHub token" -MaskInput
kubectl create secret generic github-token-secret -n argo --from-literal=token=$t
Remove-Variable t
3) check -> kubectl get secret github-token-secret -n argo

    -> jednu bump definovane v tom filu 
    -> druhou co jsme definovali vyse
2) overime: argo lint --offline workflows\dawiso-demo-smoke-test-template.yaml workflows\dawiso-demo-update-version-template.yaml
3) aplikujeme: 
4) spustime: argo submit -n argo --from workflowtemplate/dawiso-demo-update-version-template -p env=dev -p version=1.3.0 --watch
